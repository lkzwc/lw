# 订阅消息囤票方案

## 一、微信订阅消息机制

### 1.1 一次性票模型

微信订阅消息采用"一次性票"机制：

- **一次授权 = 一次发送配额**
- 用户点击授权后，服务端可向该用户发送 **1 条** 订阅消息
- 用完后需再次授权才能继续发送

### 1.2 关键限制

| 限制 | 说明 |
|------|------|
| **必须在用户 tap 事件回调中调用** | 不能在 `onShow`/`onLoad` 等生命周期中调用，微信会报错 `fail can only be invoked by user TAP event` |
| **一次可传多个 tmplIds** | `wx.requestSubscribeMessage({ tmplIds: [id1, id2] })` 一次弹窗可囤多张票 |
| **用户可拒绝或关闭"总是询问"** | errCode 20004 表示用户关闭了授权，需引导去设置页 |

## 二、囤票策略

### 2.1 分层囤票

| 层级 | 场景 | 是否强制 | 说明 |
|------|------|---------|------|
| **Tier 1（必囤）** | 评论提交后 | ✅ force=true | 评论者需囤票，别人回复时才能收到通知 |
| **Tier 1（必囤）** | 帖子作者打开自己帖子 | ✅ force=true | 有人评论时作者收到通知 |
| **Tier 1（必囤）** | 活动报名成功后 | ✅ force=true | 活动开始前收到提醒 |
| **Tier 2（低频囤票）** | 打开评论弹窗 | ❌ force=false | 用户正在看帖子，顺带囤票（受频率控制） |
| **Tier 2（低频囤票）** | 点赞 | ❌ force=false | 用户在互动，顺带囤票（受频率控制） |
| **Tier 2（低频囤票）** | 转发 | ❌ force=false | 同上（待实现） |

### 2.2 频率控制

- **Tier 1 场景**：每次都弹授权窗（评论/报名是用户明确意图，不受频率控制）
- **Tier 2 场景**：**5 分钟内不重复弹窗**，避免骚扰用户
  - 使用 `wx.getStorageSync('lastSubscribeTime')` 记录最后弹窗时间
  - 冷却期内跳过囤票

### 2.3 多模板一次弹窗

一次 `requestSubscribeMessage` 可传多个 `tmplIds`，弹一次窗囤多张票：

```javascript
// 一次弹窗囤活动提醒 + 评论回复两张票
subscribe.requestActivityReminderSubscribe(true)
```

## 三、代码实现

### 3.1 公共囤票模块 `utils/subscribe.js`

核心函数：

| 函数 | 用途 |
|------|------|
| `trySubscribe(options)` | 底层囤票函数，支持频率控制 |
| `requestCommentReplySubscribe(force)` | 请求评论回复订阅授权 |
| `requestActivityReminderSubscribe(force)` | 请求活动提醒订阅授权（一次囤两张票） |
| `requestLowFrequencySubscribe()` | 低频囤票（点赞/打开弹窗等） |
| `recordSubscription(templateId)` | 记录授权到 subscriptions 表 |
| `showSubscribeSettingGuide()` | errCode 20004 引导去设置页 |

### 3.2 改动文件

| 文件 | 改动点 |
|------|--------|
| `utils/subscribe.js` | **新增** 公共囤票模块 |
| `pages/community/community.js` | 引入 subscribe 模块，评论提交/打开弹窗/点赞时囤票 |
| `pages/post-detail/post-detail.js` | 用公共模块替换旧订阅逻辑，评论提交后囤票 |
| `pages/activity-detail/activity-detail.js` | 报名成功后囤票（一次囤两张） |

### 3.3 关键代码示例

#### 评论提交后囤票（Tier 1）

```javascript
// community.js - onSendComment
try {
  await api.comment.create({ postId, content })
  util.showToast('评论成功')

  // Tier 1 囤票（必囤）：评论者为自己囤一张票
  // force=true 表示每次评论都弹授权窗（评论是用户明确意图，不受频率控制）
  subscribe.requestCommentReplySubscribe(true)
} catch (err) {
  // ...
}
```

#### 点赞时低频囤票（Tier 2）

```javascript
// community.js - onLikeTap
try {
  await api.post.like(id, app.globalData.openid)
  // Tier 2 囤票：用户点赞互动，顺带囤一张票（受频率控制）
  subscribe.requestLowFrequencySubscribe()
} catch (err) {
  // ...
}
```

#### 活动报名后囤票（Tier 1 + 多模板）

```javascript
// activity-detail.js - onJoinTap
util.showToast('报名成功')

// Tier 1 囤票（必囤）：报名成功后请求订阅授权
// 一次弹窗囤活动提醒+评论回复两张票
// force=true 表示每次报名都弹授权窗（报名是用户明确意图，不受频率控制）
subscribe.requestActivityReminderSubscribe(true)
```

## 四、囤票时机总结

| 用户行为 | 囤票类型 | 囤几张票 | 频率控制 |
|---------|---------|---------|---------|
| 提交评论 | Tier 1 | 1 张（评论回复） | 无 |
| 帖子作者打开自己帖子 | Tier 1 | 1 张（评论回复） | 无 |
| 活动报名成功 | Tier 1 | 2 张（活动提醒 + 评论回复） | 无 |
| 打开评论弹窗 | Tier 2 | 2 张（活动提醒 + 评论回复） | 5 分钟冷却 |
| 点赞帖子 | Tier 2 | 2 张（活动提醒 + 评论回复） | 5 分钟冷却 |
| 转发帖子 | Tier 2 | 2 张（活动提醒 + 评论回复） | 5 分钟冷却（待实现） |

## 五、注意事项

### 5.1 模板 ID 配置

在 `utils/config.js` 中配置：

```javascript
subscribeTemplates: {
  commentReply: '19XJ-vNa8CD9RTDJG42yqTGklIkX0lep2o2CR50yVFI', // 已申请
  activityReminder: '' // TODO: 需在微信公众平台后台申请
}
```

### 5.2 云函数发送通知

囤票只是授权，实际发送通知需调用云函数 `sendSubscribeMessage`：

```javascript
// post-detail.js - sendReplyNotification
await wx.cloud.callFunction({
  name: 'sendSubscribeMessage',
  data: {
    openid: post._openid,
    templateId: config.subscribeTemplates.commentReply,
    data: {
      thing1: { value: '帖子标题' },
      thing2: { value: '评论内容' },
      time3: { value: '2026-06-01 12:00' }
    },
    page: `/pages/post-detail/post-detail?id=${postId}`
  }
})
```

### 5.3 通知去重

避免频繁骚扰用户，使用 `notifications` 表去重：

- 30 分钟内同一帖子同一作者不重复发送
- 记录发送时间、帖子 ID、接收者 openid
